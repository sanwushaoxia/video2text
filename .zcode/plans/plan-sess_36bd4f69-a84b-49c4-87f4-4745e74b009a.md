# 优化方案：自动识别说话人数量 + 干净分离每个说话人

## 问题根因诊断

`out_multi_v3` 的 `speaker_01.wav` 在 1:50 后串音，根因有三层：

1. **说话人数量被硬编码为 2**：`run_multi_stems_diarize.sh` 第 10-11 行 `MIN_SPEAKERS=2 MAX_SPEAKERS=2`，pyannote 被强制聚类成 2 人，1:50 后出现的第 3 个说话人被错误归并到 SPEAKER_00 或 SPEAKER_01 轨。
2. **纯时间切分不物理分离重叠**：`out_multi_v3` 用 `split_mode=diarize`，重叠段只按置信度归属一方，不做盲分离，导致串音。
3. **重叠盲分离仅支持 2 路**：`overlap_separation.py` 的 MossFormer2/SepFormer 都是 WSJ0-2mix 训练，硬编码输出 2 路，无法处理 3+ 人重叠。

## 优化方案（4 个递进改动）

### 改动 1：修正说话人数量约束（核心，立即见效）

**文件**：`scripts/run_multi_stems_diarize.sh`

把硬编码的双人约束改为"让 pyannote 自动估计"：
```bash
# 改前
MIN_SP="${MIN_SPEAKERS:-2}"
MAX_SP="${MAX_SPEAKERS:-2}"
# 改后
MIN_SP="${MIN_SPEAKERS:-1}"     # 不强制下限，让 pyannote 自由聚类
MAX_SP="${MAX_SPEAKERS:-6}"     # 放宽上限，覆盖 3+ 说话人场景
```

这样 pyannote 的 `min_speakers/max_speakers` 参数变为 `[1, 6]`，内部聚类算法会自动决定实际人数。`DiarizationResult.speaker_ids` 的长度就是真实识别出的人数，`split_report.json` 的 `stats.speaker_count` 已经在输出这个值。

### 改动 2：新增"说话人计数预检"能力

**文件**：`src/video2text/diarization.py`（新增函数）+ `src/cli/separate_audio.py`（新增 CLI 子命令 `--count-speakers`）

在 `diarization.py` 新增 `estimate_speaker_count()` 函数：
```python
def estimate_speaker_count(
    vocals_path: Path,
    *,
    max_speakers: int = 8,
    hf_token: str | None = None,
    model_id: str = DEFAULT_DIARIZATION_MODEL,
    diarize_preprocess: bool = True,
    work_dir: Path | None = None,
) -> dict:
    """仅运行日记化, 返回说话人数量与每人时长分布, 不做切分。"""
    result = run_diarization(
        vocals_path,
        min_speakers=1, max_speakers=max_speakers,
        hf_token=hf_token, model_id=model_id,
        diarize_preprocess=diarize_preprocess, work_dir=work_dir,
    )
    # 每人说话时长
    per_speaker_sec = {}
    for t in result.turns:
        per_speaker_sec[t.speaker_id] = per_speaker_sec.get(t.speaker_id, 0) + (t.end - t.start)
    return {
        "speaker_count": len(result.speaker_ids),
        "speaker_ids": result.speaker_ids,
        "per_speaker_sec": {k: round(v, 2) for k, v in sorted(per_speaker_sec.items())},
        "overlap_region_count": len(result.overlap_regions),
        "overlap_detection_source": result.overlap_detection_source,
        "turn_count": len(result.turns),
    }
```

在 `separate_audio.py` 新增 `--count-speakers` flag，调用此函数后打印 JSON 报告并退出。用户可以先跑 `--count-speakers` 确认人数，再决定 `--min-speakers/--max-speakers` 的值做精确分离。

### 改动 3：默认启用 `diarize_bss` + 放宽重叠盲分离上限

**文件**：`src/video2text/overlap_separation.py` + `src/video2text/speaker_stems.py`

当前 `MAX_OVERLAP_SEC = 3.0` 限制了重叠段时长。对于"1:50 后混入第 3 人"这种较长重叠/交替场景，需要：

1. 放宽 `MAX_OVERLAP_SEC` 到 `8.0`（或做成参数 `--max-overlap-sec`），覆盖更长的重叠区间。
2. `overlap_separation.py` 的 `separate_overlap_2spk` 增加可选参数 `n_sources`，当检测到重叠区间涉及 3+ 个 speaker_id 时，尝试调用支持多源的模型（见改动 4）。
3. `speaker_stems.py` 第 446 行 `if use_bss and diar.overlap_regions:` 已经在 `diarize_bss` 模式下自动触发，无需改逻辑，只需放宽时长约束。

### 改动 4：引入多说话人盲分离后端（可选增强，处理 3+ 人重叠）

**文件**：`src/video2text/overlap_separation.py`（新增后端）+ `requirements-separation.txt`

当前只有 MossFormer2（2 路）和 SepFormer（2 路，WSJ0-2mix）。新增一个支持可变路数的后端：

**方案 A（推荐）**：新增 SpeechBrain SepFormer 的 3mix 模型 `speechbrain/sepformer-wsj03mix`（3 说话人），根据 overlap region 涉及的 speaker_ids 数量自动选择 2mix 或 3mix：
```python
def _separate_sepformer_n(audio, sr, work_dir, *, n_sources: int) -> list[np.ndarray]:
    """n_sources 路盲分离。"""
    model_name = "sepformer-wsj02mix" if n_sources <= 2 else "sepformer-wsj03mix"
    separator = SepformerSeparation.from_hparams(

        savedir=str(speechbrain_model_dir(model_name)),
        run_opts={"device": "cuda" if torch.cuda.is_available() else "cpu"},
    )
    est = separator.separate_file(path=str(clip_path))
    # 返回 n_sources 路音频
```

修改 `apply_overlap_separation` 的逻辑：对每个 overlap region，先看 `region.speaker_ids` 的长度，决定调 2spk 还是 3spk 分离，然后用 embedding 归属到对应 speaker。

**方案 B（备选）**：引入 `speechbrain/sepformer-libri3mix`（更干净的 3 说话人模型）。或使用 ClearVoice 的 ` MossFormer2_SE_8K`（支持可变路数，但采样率只有 8k）。推荐方案 A。

## 实施顺序与验证

1. **先做改动 1**（改脚本默认值），立即验证 pyannote 能否识别出第 3 个说话人：
   ```bash
   MIN_SPEAKERS=1 MAX_SPEAKERS=6 bash scripts/run_multi_stems_diarize.sh 桔梗犬夜叉片段.mp4 ./out_multi_v4 diarize
   ```
   检查 `split_report.json` 的 `stats.speaker_count` 是否变为 3。

2. **做改动 2**（计数预检），快速诊断确认人数。

3. **做改动 3+4**（重叠盲分离增强），用 `diarize_bss` 模式处理重叠段：
   ```bash
   bash scripts/run_multi_stems_diarize.sh 桔梗犬夜叉片段.mp4 ./out_bss_v2 diarize_bss
   ```

4. **验证**：用 `scripts/compare_speaker_sep.py ./out_multi_v3 ./out_multi_v4` 对比，并人工试听 1:50 后 speaker_01 轨是否干净。

## 不改动的部分

- BS-RoFormer 人声/伴奏分离逻辑（`bs_roformer_split.py`）保持不变，它只负责背景分离
- `diarization_refine.py` 的 embedding 精修逻辑保持不变
- `pipeline.py` 主流程不涉及（多说话人分离是独立链路）
- 输出文件命名规则 `_speaker_speaker_00` 保持不变（避免破坏已有对比脚本）
